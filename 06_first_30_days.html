How I Would Add Value in the First 30 Days

A deliberately modest onboarding plan: learn the real operating model first, then improve delivery clarity and ship a visible outcome.

Days 1–10 — Learn

  • Map Brand.com components, booking / integration boundaries, CRM touchpoints, analytics, AEM governance and agency responsibilities.
  • Review backlog, release calendar, unresolved defects and definition-of-ready expectations.
  • Meet Product, Brand, Commercial, CRM, IT, Operations, QA and agency counterparts.
  • Observe ceremonies before proposing process changes.

Days 11–20 — Clarify

  • Take ownership of a contained feature / enhancement area.
  • Refine stories so business rules, dependencies, analytics, content, errors and acceptance criteria are explicit.
  • Use a lightweight open-question / decision log in the team’s existing toolset.
  • Build requirements traceability into UAT.

Days 21–30 — Deliver

  • Move a small set of stories from ambiguous to delivery-ready.
  • Coordinate business / property UAT for an active feature.
  • Produce a concise release-readiness view.
  • Capture one reusable BA pattern only if it reduces friction.
Working principle: learn Rosewood’s actual operating model first; standardise only where it reduces friction.
