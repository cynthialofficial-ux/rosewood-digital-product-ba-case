# 02 — Stakeholder Map and Working Cadence

## Core stakeholder map

| Stakeholder | What they care about | What the BA provides |
|---|---|---|
| Manager, Digital Product, Global | Product outcomes, priority, scope | Decision-ready options, backlog readiness, risks |
| Product Manager | Roadmap, sprint priorities, value | Refined stories, acceptance criteria, dependencies |
| Brand | Brand expression, content quality | Content requirements, approval rules, exceptions |
| Commercial | Conversion, offers, business value | KPI definitions, rules, experiment requirements |
| CRM | Guest identity, consent, profile continuity | Data handoffs, consent rules, exception paths |
| IT / Architecture | Integration, security, platform fit | Interface requirements, NFRs, risk / dependency log |
| Operations / Property teams | Guest fulfilment and local readiness | Process validation, UAT participation, training needs |
| External agency / Developers | Build clarity | Testable stories, edge cases, answers to open questions |
| QA | Quality and regression coverage | Traceability, expected outcomes, defect triage |

## Suggested BA cadence

**Discovery / definition**
- Requirement workshops by functional domain.
- Confluence decision log.
- Story-map review with Product Manager.
- Weekly dependency / open-question review.

**Sprint delivery**
- Backlog refinement.
- Sprint planning support.
- Developer / QA clarification during sprint.
- Mid-sprint content and dependency check.
- Demo acceptance against agreed criteria.

**Release**
- UAT coordination with business and property users.
- Go / no-go checklist.
- Known-issues and support handover.
- Post-release KPI / defect review.
