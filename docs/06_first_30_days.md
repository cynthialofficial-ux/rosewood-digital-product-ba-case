# 06 — How I Would Add Value in the First 30 Days

## Days 1–10 — Learn the real operating model

- Map the live product landscape: Brand.com components, booking / integration boundaries, CRM touchpoints, analytics, AEM governance and agency responsibilities.
- Review the active backlog, release calendar, unresolved defects and current definition-of-ready expectations.
- Meet Product, Brand, Commercial, CRM, IT, Operations, QA and key agency counterparts.
- Observe ceremonies before proposing process changes.

## Days 11–20 — Improve delivery clarity

- Take ownership of a contained feature / enhancement area.
- Create or refine stories so business rules, dependencies, analytics, content, errors and acceptance criteria are explicit.
- Establish a lightweight open-question / decision log in the team's existing toolset.
- Build requirements traceability into UAT rather than treating UAT as a late-stage activity.

## Days 21–30 — Deliver a visible outcome

- Move a small set of stories from ambiguous to delivery-ready.
- Coordinate business / property UAT for an active feature.
- Produce a concise release-readiness view showing requirements, content, integration, UAT and analytics status.
- Capture one reusable BA pattern for the team (for example, a story template, content-readiness checklist or UAT traceability format) only if it improves the team's current process.

## Working principle

**Learn Rosewood's actual operating model first; standardise only where it reduces friction.**
